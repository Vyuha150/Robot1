# requirements/pi2_requirements.txt
#
# Real Python dependencies for Pi-2 (Human AI) optional backends. None of
# these were previously declared anywhere in the repo -- every bonbon_*
# package.xml / setup.py only lists python3-numpy / python3-opencv
# (resolvable via rosdep), while insightface/whisper/ollama/chromadb/
# mediapipe/torch/etc. are all lazy-imported (`try: import X` inside a
# function, wrapped so a missing backend degrades honestly rather than
# crashing at module load -- same pattern as every bonbon_hal driver's
# DriverFault("SDK_MISSING")). That's correct for graceful degradation,
# but it also meant nothing actually installed these packages anywhere.
# This file is the missing manifest, consumed by deployment/docker/
# Dockerfile.ai's `pip3 install -r requirements/pi2_requirements.txt`.
#
# ARM64/CPU-only notes (Raspberry Pi 5, no CUDA):
#   - torch: install the CPU-only wheel index, never the CUDA build.
#   - faster-whisper only, openai-whisper deliberately NOT installed
#     (bonbon_speech/stt/whisper_stt.py supports both as selectable
#     backends via stt_backend, never both at once). faster-whisper uses
#     CTranslate2 (int8-quantized, CPU-optimized) -- meaningfully faster
#     than openai-whisper's raw PyTorch inference on an ARM CPU with no
#     GPU, and openai-whisper's own package additionally hard-depends on
#     `triton` (an NVIDIA GPU-kernel-compilation library), which drags in
#     the full CUDA toolkit exactly like the numba/cuda-bindings problem
#     above -- confirmed on a real build attempt (`Collecting triton==3.7.1`,
#     184.6 MB, immediately followed by more nvidia-* packages). Shipping
#     both backends when only one is ever selected was already borderline
#     redundant; once one of them turned out to actively break the build
#     on this hardware, dropping it was the clear call. Switching to
#     openai-whisper later remains a one-line requirements + launch-arg
#     change if ever needed.
#   - deepface intentionally NOT installed: bonbon_vision/face/
#     face_pipeline.py treats insightface and deepface as ALTERNATIVE
#     face backends, not complementary ones (deepface recognition is
#     skipped entirely whenever insightface handles detection). Installing
#     both would mean shipping two overlapping, heavy face stacks
#     (deepface pulls in TensorFlow/Keras) when only one is ever used --
#     exactly the redundancy this deployment must avoid. insightface
#     alone covers both face detection and recognition.
#   - faiss-cpu NOT installed by default: bonbon_llm's RAGConfig defaults
#     to backend="chroma" (config/llm/llm_config.py); faiss is only the
#     alternative backend. Add faiss-cpu only if you deliberately switch
#     rag.backend to "faiss".
#   - mediapipe: historically had incomplete/lagging aarch64 Linux wheel
#     availability -- flagged as a real installation risk, not assumed to
#     "just work". If pip has no matching wheel for this Python/arch
#     combination, this is a genuine, reportable BLOCKER for
#     bonbon_gesture's real backend, not something to silently skip.
#   - numba pinned to <0.59: a transitive dependency somewhere in this
#     chain (numba is pulled in indirectly, not listed directly by us --
#     likely via librosa under pyannote.audio/faster-whisper) requires
#     cuda-bindings on newer numba releases, which in turn pulls the
#     ENTIRE NVIDIA CUDA toolkit metapackage (cudnn, nccl, triton,
#     cusparse, nvjitlink, ...) -- multiple gigabytes of GPU packages
#     with zero use on a Raspberry Pi 5 (no NVIDIA silicon at all).
#     Discovered when a real build attempt sat backtracking through
#     dozens of nvidia_ml_py/cuda-toolkit version combinations for over
#     40 minutes before being killed. Pinning below 0.59 avoids the
#     unconditional CUDA dependency entirely.
#   - nvidia-ml-py pinned to a single version for the same reason:
#     ultralytics-thop wants it, but leaving it unpinned let pip's
#     resolver backtrack through dozens of releases trying to satisfy
#     other constraints. It's a tiny pure-Python GPU-query binding either
#     way (installs fine with no GPU present; simply never used).

# Transitive-dependency pins (see ARM64/CPU-only notes above) -- these are
# not directly imported by any bonbon_* package, they exist purely to stop
# pip's resolver from pulling the NVIDIA CUDA toolkit onto a GPU-less Pi.
numba<0.59
nvidia-ml-py==12.560.30

ultralytics
insightface
onnxruntime

pyannote.audio

mediapipe
